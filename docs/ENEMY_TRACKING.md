# Запись положения врага в replay (план)

**Статус:** план, не реализовано. Цель — записывать положение ближайшего
врага вместе с вводом в кадрах Record/Playback, чтобы офлайн сопоставлять
кадры воздушной атаки игрока с состоянием врага и использовать данные для
**сдвига тайминга** воспроизведения.

## Зачем

В бою P310 (EmSetCorps) механика воздушной атаки игрока:

- «Прыжок» врага — это **анимация 65545** (пик ~0.5 с), поднимающая **части
  модели** (клинок до 2.97 м), а корень врага остаётся на земле (Y≈0).
  Анимация 19 — выпад по земле (клинок ~1.13 м), idle — ~1.03 м.
- Игрок делает air-атаку (в записи 117: прыжок fi=45 → удар fi=76 на высоте
  0.507 м); направление удара задаётся позицией врага в этот момент.

Сейчас в replay записываются только игрок и камера — состояние врага
недоступно офлайн. Для анализа «ориентироваться на врага» (и последующего
сдвига тайминга подачи кадров) нужны данные врага в каждом кадре записи
и воспроизведения.

## Что записывать (на кадр)

Ближайший к игроку враг (по дистанции):

| Поле | Смещение/источник |
|---|---|
| pos (мировая X/Y/Z) | behavior `+0x50/0x54/0x58` |
| blade_y (мировая высота клинка) | `Em0010_Blade` матрица cParts `+0x10` → `m[3].y` = `+0x44` |
| r_anim (анимация врага) | behavior `+0x618` |
| frame (кадр анимации) | behavior `+0x8B4` |
| hp | behavior `+0x870` |

## Найденные адреса и связи (подтверждено рантаймом 2026-08-23)

- `EntitySystem::ms_Instance` = `base + 0x17E9A98`; список `m_EntityList` на
  `+0x38` (cFixedList: size `+0x0C`, first `+0x14`, узел `+0x08`).
- Entity: имя `+0x04`, Behavior (m_pSceneModel) `+0x3C`.
- Иерархия частей: `Em0010_Blade.owner (+0x518) → Em0160Body (+0x360) →
  EmSetCorps`. `+0x50` у частей — локальная позиция (0); мировая — из матрицы
  cParts (+0x10 → m[3] = +0x40/+0x44/+0x48).
- Фильтр врагов: имена `Em*`/`Ba*`/`Pl001*` (не игрок), pos != (0,0,0),
  HP 1..1_000_000 (см. `read_enemies` в `src/lib.rs` — готовая логика).

## План реализации

1. **`src/tas/types.rs` — расширить `ReplayFrame`**: `enemy_pos: [f32; 3]`,
   `enemy_blade_y: f32`, `enemy_anim: i32`, `enemy_hp: i32` (или один
   компактный struct). Версионирование layout — по размеру BLOB (как camera).
2. **Запись (`src/tas/replay.rs`, record)**: каждый кадр снимать ближайшего
   врага. Логику чтения вынести из `read_enemies` (debug-only) в общий
   модуль/функцию, доступную и в release-записи, или продублировать минимально
   (чтение EntitySystem + поиск ближайшего + bladeY).
3. **Playback**: писать в кадры playback-фреймов то же (фактическое состояние
   врага во время воспроизведения).
4. **`tools/dbdump`**: добавить колонки `enemy_pos_x/y/z`, `enemy_blade_y`,
   `enemy_anim`, `enemy_hp` в схему (83 → 88) — экспорт в CSV/Parquet.
5. **Анализ (`tools/desync_analysis/`)**: новый скрипт — сопоставление кадров
   air-атаки игрока (по вводу/r_anim игрока) с `enemy_pos`/`enemy_blade_y`
   в record и playbacks. Цель — понять, как недетерминизм врага коррелирует
   с десинком траектории игрока.

## Применение: сдвиг тайминга

Идея (уточнить после первых данных): если у воспроизведения момент/высота
air-атаки игрока относительно врага систематически смещены, подстраивать
подачу кадров (сдвиг `next_idx`, дубль/пропуск кадра в варианте D/E стиле)
под совпадение фазы «враг в атаке» (anim 65545/19, blade_y) с записью.
Данные врага в playback-кадрах дадут метрику рассогласования.
