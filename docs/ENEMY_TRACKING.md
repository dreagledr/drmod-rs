# Запись положения врага в replay

**Статус:** реализовано (2026-08-24). Кадры Record/Playback содержат состояние
ближайшего к игроку врага (`EnemyState`), экспортируются dbdump в колонки
`enemy_*` и анализируются `tools/desync_analysis/analyze_enemy.py`. Цель —
офлайн сопоставлять кадры воздушной атаки игрока с состоянием врага и
использовать данные для **сдвига тайминга** воспроизведения.

## Зачем

В бою P310 (EmSetCorps) механика воздушной атаки игрока:

- «Прыжок» врага — это **анимация 65545** (пик ~0.5 с), поднимающая **части
  модели** (клинок до 2.97 м), а корень врага остаётся на земле (Y≈0).
  Анимация 19 — выпад по земле (клинок ~1.13 м), idle — ~1.03 м.
- Игрок делает air-атаку (в записи 117: прыжок fi=45 → удар fi=76 на высоте
  0.507 м); направление удара задаётся позицией врага в этот момент.

Сейчас в replay записываются только игрок и камера — состояние врага
недоступно офлайн. Для анализа «ориентироваться на врага» (и последующего
сдвига тайминга подачи кадров) нужны данные врага в каждом кадре записи
и воспроизведения.

## Что записывается (на кадр)

Ближайший к игроку враг (по дистанции) — `EnemyState` (32 байта, `repr(C)`,
в `replay-types`):

| Поле | Смещение/источник |
|---|---|
| `pos` (мировая X/Y/Z) | behavior `+0x50/0x54/0x58` |
| `blade_y` (мировая высота клинка) | `Em0010_Blade` матрица cParts `+0x10` → `m[3].y` = `+0x44` |
| `r_anim` (анимация врага) | behavior `+0x618` |
| `frame` (кадр анимации) | behavior `+0x8B4` |
| `hp` | behavior `+0x870` |
| `found` | 1 — враг найден, 0 — врага нет (не бой/loading) |

## Найденные адреса и связи (подтверждено рантаймом 2026-08-23)

- `EntitySystem::ms_Instance` = `base + 0x17E9A98`; список `m_EntityList` на
  `+0x38` (cFixedList: size `+0x0C`, first `+0x14`, узел `+0x08`).
- Entity: имя `+0x04`, Behavior (m_pSceneModel) `+0x3C`.
- Иерархия частей: `Em0010_Blade.owner (+0x518) → Em0160Body (+0x360) →
  EmSetCorps`. `+0x50` у частей — локальная позиция (0); мировая — из матрицы
  cParts (+0x10 → m[3] = +0x40/+0x44/+0x48).
- Фильтр врагов: имена `Em*`/`Ba*`/`Pl001*` (не игрок), pos != (0,0,0),
  HP 1..1_000_000 (см. `read_enemies` в `src/game/player.rs`).

## Реализация

1. **`replay-types/src/lib.rs`** — `EnemyState` (pos/blade_y/r_anim/frame/hp/
   found). BLOB-колонка `enemy` в таблицах `replay_*_frames` (32 байта,
   версионирование по размеру, как camera).
2. **`src/game/player.rs`** — `EnemyInfo` дополнен `anim_frame` (+0x8B4);
   новый `read_nearest_enemy() -> EnemyState` переиспользует обход
   `read_enemies` и выбирает ближайшего по `dist`.
3. **Запись (`src/tas/replay.rs`)** — `ReplayFrame.enemy`; `update` принимает
   `EnemyState` и пишет его и в record-кадры (`capture_frame`), и в
   playback-лог (`playback_tick` — фактическое состояние врага во время
   воспроизведения).
4. **`src/lib.rs`** — чтение врага гейтится: только пока активны
   запись/воспроизведение (`replay.is_active()`) и не loading
   (`menu_status`), чтобы не гонять обход EntitySystem каждый кадр.
5. **`src/tas/db.rs`** — колонка `enemy BLOB` в CREATE + миграция
   (`ensure_replay_frame_columns`) + bulk-insert.
6. **`tools/dbdump`** — колонки `enemy_pos_x/y/z`, `enemy_blade_y`,
   `enemy_anim`, `enemy_frame`, `enemy_hp` (83 → 90). Старые БД без колонки
   дают NULL (динамическое чтение, как raw_down).
7. **`tools/desync_analysis/analyze_enemy.py`** — окна air-атаки игрока
   (JUMP pressed → LIGHT_ATTACK pressed при pos_y > 0.3), таблица состояния
   врага по кадрам окна в record и playbacks, метрики в момент удара
   (|Δenemy_pos|, blade_y, фаза анимации врага).

## Применение: сдвиг тайминга

Идея (уточнить после первых данных): если у воспроизведения момент/высота
air-атаки игрока относительно врага систематически смещены, подстраивать
подачу кадров (сдвиг `next_idx`, дубль/пропуск кадра в варианте D/E стиле)
под совпадение фазы «враг в атаке» (anim 65545/19, blade_y) с записью.
Данные врага в playback-кадрах дадут метрику рассогласования.
