# Грабли и «что не работает» — сводка по проекту

> **Документ-история.** Собирает отрицательные результаты, тупики и технические ловушки,
> чтобы не повторять их. Текущее состояние фич описано в `../QWEN.md`, `API.md`, `PHASE.md`,
> `REPLAY.md` и README инструментов; здесь — только «не работает / сломалось / надо помнить».
> Детальные разборы — в профильных доках (ссылки в разделах).

## Сборка и окружение

- **`tools/dbdump` и `server/` — под x64**, у каждого свой `.cargo/config.toml` (arrow-rs только
  64-bit). Корневой `cargo build --release` (i686) их **не** собирает — только из своей директории.
- **`mods/cutscene_skip/`** — отдельный крейт со своим `[workspace]`/`target`, в корневой
  workspace не входит.
- **Запуск мода для тестов:** инжектить через `cargo run` (прямой запуск `drmod.exe` тригерит
  подтверждение пользователя); саму игру поднимать `py -3 tools/script_tuning/launch_game.py`
  (`--no-inject`, мод потом отдельно). См. `../tools/script_tuning/README.md`.
- **Инструменты печатают UTF-8** (`api.setup_stdout()`): в cp1251-консоли — кракозябры, а
  символы `→`/`≥`/`✓` роняли печать уже после записи CSV (так потерялись две сводки).
- **Две копии игры на одной машине — нельзя** (разведано и откачено 2026-09-13): вторая копия
  MGR:R умирает с кодом 0 через ~100 мс после загрузки `steam_api.dll` (локально, независимо от
  пути exe / `appid` / env). Форс успеха обеих ветвей `SteamAPI_Init` (`0x5819C9`/`0x581CB9`)
  не помогает — гибнет внутри `steam_api.dll`. Сейвы игра ведёт через Steam Cloud
  (`SteamRemoteStorage`), файл один на пару (steamid, appid). Для параллельных прогонов сначала
  нужна изоляция Steam-контекста и папки сейвов.

## Дизассемблирование (детали — `../tools/disasm/README.md`)

- **Адрес в файле ≠ адрес в памяти.** `dump.ps1` / `scan_calls.ps1 -Mem` / `peek.py` читают
  **память** (адреса с релокацией `base`), а `scan_srm.py` / `disasm.py` / `find_*` — **файл**
  (`ImageBase + RVA`). `base` меняется от запуска к запуску (2026-08-16 — `0x370000`,
  2026-09-11 — `0x930000`). `call rel32` (E8) от релокации не зависит — его можно искать в файле.
- **`[abs32]` в инструкциях — это file VA** (`0x400000 + RVA`), а не runtime-адрес: в
  дизассемблере глобал `base + 0x17EA140` виден как `[0x1BEA140]`.
- Прямых `call` к геттерам времени движка нет — они зовутся **косвенно (через vtable)**, поэтому
  потребители ищутся только хуком или через vtable-таблицы.

## Ввод (детально — `REPLAY_FINDINGS.md`, `INPUT_STATUS.md`)

- Прямая запись в `Present` — **поздно** (после `handleActions`); прямая запись в сырые кэши
  (`ms_KeyInput`/`ms_InputKeys`/`ms_MouseStateInput`) — **игрок их не читает**.
- `SendInput` / `keybd_event` фронтенд игры **не принимает**; меню подаётся мод-каналом (DIK-биты).
- `isKeybindDown` (`0x61D280`) ≠ `isKeybindPressed` (`0x61D2D0`): для активаций (ripper и др.)
  нужен **pressed**; для удержаний — down.
- Меню-клавиши (стрелки/Enter) — **не keybind'ы**: читаются `KeyInput::isKeyDown/isKeyPressed`
  (`0x9D93A0`/`0x9D9400`) из кэша `ms_KeyInput`.
- Биты `InputUnit` (подтверждено рантаймом): `0x1` — **меню оружия** (не прыжок!), `0x8` — AR,
  `0x10` — прыжок/confirm, `0x20` — лёгкая атака (в меню — отмена), `0x100` — Esc/START.
- Кадр API-скрипта должен подаваться **по тику симуляции** (детур `updateInputUnit`), а не по
  кадрам отрисовки: иначе при 43–57 FPS один и тот же кадр попадал в разные моменты физики
  (связка давала то 5/8, то 0/15).

## Катсцены / фазы (детально — `PHASE.md`)

- **`changePhase` `0x8E3040`** на смену подфазы **не влияет** — `POST /phase` оставлен как
  задокументированный отрицательный результат.
- **Правка блока «чекпойнт»** (`+0x08/+0x0C/+0x10`) + штатный рестарт — подмена игнорируется
  (рестарт восстанавливает состояние из сохранённого буфера).
- **Ручная запись «заявки» + состояния `0x12`** (не через `0x94E1F0`) **роняет игру** — заявку
  делать только вызовом `0x94E1F0`.
- Собственный пункт **Skip консольного меню на PC инертен**, а шаг 5 обработчика непроходим
  (`0x1DC203C` — константа `1.0f`, условие `0 < 1.0` всегда истинно) → меню висит; уборка меню
  и заказ подфазы делаются снаружи (мод/инструмент).
- **Пауза (`STA_PAUSE`, код 19) стопорит загрузку сцены** — заказ подфазы грузит сцену только
  **без паузы**. `STA_EVENT` в `staFlags` тоже заставляет движок игнорировать заказ.
- **Esc сам консольное меню не открывает**: физический Esc даёт бит `0x100` в `down`, но **не
  даёт фронт** (`pressed`), а движковая проверка паузы в событии срабатывает по фронту. Подача
  `pause`/DIK-Esc **из мода** меню тоже не открывает — открывает только физический Esc игрока.
- `POST /dt` (шаг 1000 мс) сцену **не ускоряет** — она ждёт звук монолога.
- Сейв `MGR.sav` **шифрован** — патч сейва не проходит.

## DLL в живой игре

- **Горячая перезагрузка DLL** (`POST /eject` → повторный инжект) приводила к крешам
  (`0x80000003` / `0xC000001D` / `0xC0000005` по адресу внутри DLL): остаточный хук/трамплин
  указывает в выгруженный код. Рабочий обход — **не перезагружать DLL на ходу**, а поднимать
  игру заново (`launch_game.py --kill-first`) и инжектить один раз. По договорённости креши не
  лечили. Были падения и на рестарте (в фазе меню/загрузки).
- **Фаза рестарта требует фокуса окна игры**: игра опрашивает клавиатуру (`DirectInput`) только в
  foreground; инструменты активируют окно сами.
- Хуки `POST /dt` / `/rng` / `/fps` ставятся **и в release** (HTTP API доступен в обеих сборках).
