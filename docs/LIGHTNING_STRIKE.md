# Lightning Strike — приём `вперёд, вперёд, хэви` (`anim 110`)

Наземный рывок Райдена: два нажатия `вперёд` и `heavy`. В MGR:R его применяют в
цепочке против стены и «в воздухе» с барьера — важен **тайминг ударов**, а не
перемещение (рывок упирается в геометрию, анимация и тайминги те же).

## Что выяснилось и почему скриптом не воспроизводилось

Вручную приём выходил, из скрипта (`POST /script/run`) — нет: игра видит
«вперёд, вперёд, хэви», но у скрипта не получалось **повторного нажатия**
`вперёд`. Причина — в моде: `src/api.rs` для движений (`FORWARD/BACK/LEFT/RIGHT`)
выставлял только `buttons_down` (удержание), а фронт (`buttons_pressed`) — лишь у
`jump/light/heavy/ninja/blade`. Игра считает `pressed` как «бит появился на этом
кадре», поэтому удержанный `forward` нового нажатия не давал и вместо `110`
выходил обычный наземный `heavy` (`anim 81`).

**Правка:** в `src/api.rs` движения теперь тоже ставят фронт — когда бит
направления появляется заново (сверка с предыдущим кадром), то есть ровно та же
семантика, что у игры.

## Рецепт (проверено вживую)

Пара ввода:

| кадр | ввод |
|------|------|
| `t` .. `t+2` | `forward` + `blade` (тап; одновременно — по «как на консоли») |
| `t+4` .. | `forward` + `heavy` (`heavy` держать ~6 кадров) |

Итог пары: `blade` заводит Blade Mode (`anim 69`, ~5–7 кадров), BM сам выходит,
и `forward`+`heavy` даёт **`anim 110`** — lightning strike.

Зависимости (свипы вживую):

- пауза между тапами `2` кадра → `81`; **`≥4`** → `110` (6 из 6);
- `blade` в первом тапе можно и не подавать — с ним BM включается и уходит сам,
  на выход приёма это не влияет;
- «жать только с места» — **не условие**: при паузе 10–16 игрок уже бежит
  (`anim 3/5`) и удар всё равно выходит. Ключ — свежий фронт `вперёд`;
- `ninja_run` + `вперёд` + `heavy` — это **другое** движение (`anim 94`,
  лаунч-полёт), не путать.

## Зацикливание

Одна пара на цикл, период `period` кадров. При `period ≥ 44` **каждая пара даёт
ровно один цикл** `BM(69) → 0 → приём(110)`:

```
period 52, heavy 6, 8 пар:
69x7 0 110x44 | 69x6 0 110x45 | 69x7 0 110x44 | 69x7 0 110x44 |
69x5 0 110x46 | 69x7 0 110x44 | 69x7 0 110x44 | 69x7 0 110x1
```

`110`-отрезков: **8 из 8**. При `period` 20–30 удар приходится через пару
(цикл ≈ 2×период) — половина пар уходит впустую.

**Длину удара задаёт период:** `110 ≈ period − 7`, потому что анимацию обрывает
следующий тап `forward`+`blade`. То есть «кадр зацикливания» — это и есть
длительность приёма, её можно выбирать (44…60+).

## R-03 TAS baseline (связка целиком)

Зафиксированная базовая связка для R-03 (перелёт барьера + приём + фоллинг-лайтнинг
+ риппер). Мир: `/dt {"fixed": true}` + `/rng {"pin":"freeze","seed":1}` +
`trigger.ticks=0` + рестарт миссии — прогон воспроизводится бит-в-бит.
Инструмент: `tools/script_tuning/r03_baseline.py` (тайминги — его опции).

| кадр | что | поз. |
|------|-----|------|
| 0–78 | `core117`: разгон, прыжок, тяжёлая с `ninja` — лаунч `94` | спавн `z=70.9` |
| 174 | пик перелёта `y = 21.48` | `z ≈ 46.8` |
| 186–196 | удержание BM (`blade`) — посадка и **стойка на барьере** (`anim 69`) | `(−7.17, 20.04, 47.41)` |
| 210 / +4 | пара: тап `вперёд`+`blade`, затем `вперёд`+`heavy` | `y = 20.00` |
| 222–264 | **lightning strike `110`** с барьера (48 кадров) | сносит вперёд |
| 266 / 270 | вторая пара: тап `blade` = **кансел** `110`; `heavy` = фоллинг | `y ≈ 15` |
| 276–… | **falling lightning `94`** — полёт вниз | `z ≈ 33` |
| **300** | **риппер** (+30 кадров к тяжёлой, в полёте) | `y = 14.55` |
| ~346 | посадка на землю, `94` продолжается | `y = 0.11` |
| конец | `(−21.17, 0.11, 2.81)`, `ripper = 1` | ~50 м от барьера |

Серия анимаций (по кадрам): `0x34 71x6 5x39 94x112 11x1 69x13 11x3 12x3 69x7 0x1
110x48 69x7 11x1 94x147`.

Параметры (значения по умолчанию `r03_baseline.py`): `jump=39`, `run_frames=6`,
`attack=78`, `dur_attack=24`, `ripper=112`, `release_tail=6`, `end=206`,
`bm_start=186`, `bm_end=196`, `pair_start=210`, `strikes=2`, `period=56`,
`heavy_dur=6`, `ripper_after=30`.

Что критично:

- `end` у `core117` обязан кончаться **до** первой пары: хвост держит
  `ninja_run`+`forward`, а с ninja `forward`+`heavy` даёт лаунч `94`, не приём.
- риппер — **в полёте** (~+30 к тяжёлой): он удлиняет `falling lightning` до
  самой земли. При +60/+90 он попадает уже после посадки и удлинения не даёт.
- чтобы увидеть посадку, нужен маркер вдали (`--tail`, `camera_reset`): мод пишет
  кадры только пока идёт скрипт, иначе лог обрывается в воздухе.

## Как это измерялось

- Разбор ручного исполнения по кадрам: `tools/script_tuning/lightning_strike.py`
  умеет свипы `--gaps` (пауза внутри пары), `--offsets` (кадр второй пары),
  `--periods` (серия пар); печатает сжатую серию анимаций (`69x7 0 110x44`) и
  число отрезков `110`.
- Вход игрока видно в `/logs` по кадрам (`input.down_bits` / `input.pressed_bits`
  — это `m_CurrentInput`, то есть реальный ввод тоже): `out/watch_input.py` в
  песочнице печатал только изменения, по нему и был снят паттерн.

## Замечания

- Замеры делались без рестарта, на живом игроке (мир — `dt fixed` + `rng freeze
  seed 1`); пробы требуют устойчивой нейтрали перед пуском (`anim 0`, скорость
  ≈ 0), иначе удар может попасть на бег/стан.
- Скриптовая длительность удара ограничена скриптом (период); при обрыве
  скрипта анимация обрезается.
- Позиция для «замера дальности» не показательна (в стену не едет) — критерий
  тут тайминговый.
