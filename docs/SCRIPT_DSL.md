# DSL скриптов ввода (`.tas`)

Текстовый формат скрипта — того же самого, который принимает `POST /script/run`
(§4 в [`API.md`](API.md)). Файл читается человеком и LLM, а конвертер редактора
(`tas-editor-cs/`) держит его в обе стороны с JSON.

> **Статус:** формат v2 (консольная лексика, движение стиком). Изменения — только
> через этот документ. Реализация: `tas-editor-cs/TasEditorCs/Script/`
> (`ScriptDsl.cs` — текст, `ScriptJson.cs` — JSON, `ScriptDocument.cs` /
> `ScriptCommand.cs` — модель, `ScriptFrames.cs` — проекция в кадры таблицы).

Пример (он же golden-файл `Fixtures/rules_ticks.expected.tas`):

```
! name=r03-barrier-ticks trig=ticks:0
0 ls:0:6
6 ls:0:2 a:2
20 ls:0:24 y:24
```

---

## 1. Формат файла

- UTF-8, расширение `.tas`, строки разделены `\n` (CRLF читается).
- Пробельные строки игнорируются; `#` начинает комментарий — на всей строке или
  в хвосте: `0 ls:0:6  # разбег`.
- Токены в строке разделяются пробелами; **регистр не важен** (`LS:0` = `ls:0`),
  канонический вид — строчные буквы.
- Не более одной строки правил, и она обязана идти первой.

## 2. Строка правил

Начинается с `!`, дальше — атрибуты через пробел. Все атрибуты соответствуют
полям тела `POST /script/run`, кроме прогонных ручек (см. §6).

| Атрибут | JSON | Смысл |
|---------|------|-------|
| `name=<строка>` | `name` | Имя скрипта (≤ 64 символа, **без пробелов и `#`** — иначе текст его не выразит, и конвертер отдаёт ошибку). По умолчанию `script` — как у мода. |
| `trig=pos:x,y,z` | `trigger.pos` | Зона старта: ±0.1 м по X/Z, ±1.0 м по Y. |
| `trig=ticks:N` | `trigger.ticks` | Старт через N тиков симуляции в геймплее (воспроизводимая фаза врага). |
| `restart` | `restart: {}` | Рестарт миссии из меню паузы с дефолтными параметрами мода. |
| `restart:<k=v,…>` | `restart` | То же с не-дефолтными параметрами. |

Параметры `restart` — в именах JSON: `ups` (1), `downs` (0), `hold` (6),
`open_gap` (20), `gap` (10), `confirms` (2), `confirm_gap` (25), `tail` (15);
в скобках — дефолт мода. В текст пишутся **только отличающиеся**, поэтому
`restart:ups=2,downs=1` значит «остальное как в игре». `pos` и `ticks` можно
задать одновременно (мод требует хотя бы один).

Строка правил опциональна: без неё имя — `script`, триггера и рестарта нет.

## 3. Строки кадров

```
<кадр> [<токен>[:<кадры>]] …
```

- **Кадр** — номер тика симуляции (0-based). В геймплее кадр скрипта = тик
  симуляции, в меню/загрузке (где тика ввода нет) — кадр отрисовки (`API.md` §4.1).
- Одна строка — один кадр; строки идут по возрастанию кадра, но парсер их не
  требует упорядоченными.
- Строка без токенов (`300`) — маркер: ничего не подаёт.
- **Токен входа** — имя кнопки пада, который мод эмулирует; `:<кадры>` — сколько
  кадров держать, по умолчанию **1**, и тогда двоеточие не пишется.
- Токены одной строки с **разной** длительностью дают разные команды JSON:

```
0 ls:0:10 x:2      →  { "t": 0, "duration": 10, "input": { "left_stick": [0, -1000] } }
                      { "t": 0, "duration": 2,  "input": { "light_attack": true } }
```

- Один и тот же вход в строке дважды — ошибка (`line 3: 'jump' is given twice`).

### 3.1. Таблица токенов

Имена — консольного пада (`PS / Xbox`), и они же стоят заголовками колонок
таблицы команд, так что шапка грида служит легендой текста.

| Токен | JSON-ключ (`input`) | Что это (по паду) |
|-------|--------------------|-------------------|
| `a` | `jump` | X / A — Jump |
| `b` | `zandatsu` | Circle / B — Zandatsu / Ninja Kill |
| `x` | `light_attack` | Square / X — Light attack |
| `y` | `heavy_attack` | Triangle / Y — Strong attack |
| `by` | `heavy_attack` + `zandatsu` | Y+B — Execute (одна строка, две команды) |
| `lt` | `blade` | Hold L1 / LT — Blade mode |
| `rt` | `ninja_run` | Hold R1 / RT + LS — Ninja Run |
| `lb` | `subweapon` | R1 / RT (с L2/LB) — под-оружие |
| `rb` | `lock_on` | R2 / RB — Toggle lock on |
| `r` | `camera_reset` | R3 — Centre Camera |
| `lr` | `ripper` | L3 + R3 — Ripper Mode |
| `ax` | `dodge` | Square+X / X+A + LS — Evade |
| `du` | `ar_mode` | D-Pad Up — Augment mode |
| `dd` | `item` | D-Pad Down — Use recovery item |
| `dl` / `dr` | `weapon_select` | D-Pad Left / Right — Access inventory (в моде один флаг, канон `dl`) |
| `mu` `md` `ml` `mr` | `menu_up/down/left/right` | D-Pad в меню |
| `ok` | `confirm` | подтверждение (Xbox A) |
| `esc` | `pause` | Start / Esc — Pause |
| `cd` | `codec` | Select / Back — Codec |
| `wk` | `walk` | шаг: половинная магнитуда левого стика |
| `ls` `lsx` `lsy` | `left_stick` | левый стик (см. §4) |
| `rs` `rsx` `rsy` | `camera` | правый стик / камера (см. §4) |

**Чего в списке нет:** четырёх флагов направлений (`forward`/`backward`/`left`/
`right`). Движение в тексте — это стик (см. §4): у пада нет «кнопки вперёд», и
игра двигает персонажа по стику, биты направлений не обязательны
(`API.md` §10.2, проверено явным `left_stick` на диагоналях). Флаг, который несёт
JSON, при записи в текст **сворачивается в стик**, который он подразумевает.

## 4. Стики

```
ls:<угол>[:<кадры>]        полное нажатие левого стика
lsx:<значение>[:<кадры>]   точное значение оси X (±1000), ось Y — что сказано или 0
lsy:<значение>[:<кадры>]
rs:<угол>[:<кадры>]        полное нажатие камеры (правый стик)
rsx:<значение>[:<кадры>]   точные значения камеры: сотни–тысячи (мышь до ~±6500)
rsy:<значение>[:<кадры>]
```

- **Угол — компас:** `0` — вперёд (вверх), дальше по часовой: `90` вправо,
  `180` назад, `270` влево. Так пишут «падовым» мышлением: `ls:0` = стик вверх.
- **Полное нажатие** = 1000 по направлению: `x = 1000·sin(угол)`,
  `y = −1000·cos(угол)`. Обе оси в шкале пада, поэтому `ls:0` и `rs:0` — одна
  магнитуда.
- **Точные значения** (`lsx`/`lsy`/`rsx`/`rsy`) пишут оси как есть — так в текст
  попадают частичные стики (`lsx:300`), угловые диагонали (`lsx:1000 lsy:-1000` —
  то, что мод собирает из двух направлений, магнитуда 1414) и быстрый разворот
  камеры (`rsx:6500`).
- **`wk` половинет левый стик** (игра кодирует шаг магнитудой: ручная ходьба даёт
  `[0, -500]`, `API.md` §4.2). Пишется как флаг: `0 ls:0 wk:90` — шагом вперёд.
  Половинение делает мод (и таблица команд), текст хранит полное нажатие.
- Обе формы на одной строке для одной оси/стика — ошибка; два разных стика одной
  стороны в одной строке (две команды с разными `left_stick` на одном кадре) —
  тоже: строка говорит один стик на сторону.
- Пустой/нулевой стик — `lsx:0` (нулевая ось не пишется, её отсутствие и значит 0).
- Точность: значения округляются до тысячных, углы — до тысячных градуса; это
  много точнее того, что читает игра (пороги — сотни).

## 5. Каноническая форма

`Write` детерминирован: один и тот же документ всегда даёт один и тот же текст.
Это то, что лежит в golden-файлах и что сравнивают тесты.

- Одна строка на каждый кадр, задетый хотя бы одной командой, по возрастанию.
- Порядок токенов: сначала стики (`ls`, `rs` — или их точные формы), дальше
  входы в порядке колонок таблицы команд.
- Длительность 1 не пишется; числа — инвариантная культура, кратчайшая запись.
- Полное нажатие пишется углом, всё остальное — осями; нулевая ось не пишется.
- `y` и `b` с одинаковой длительностью сворачиваются в `by`
  (`0 y:5 b:3` — когда длительности разные, `0 by:5` — когда совпадают).
- Один булев вход в нескольких командах одного кадра → один токен с **самой
  длинной** длительностью: мод объединяет биты всех активных команд.
- `Write(Parse(text))` возвращает тот же текст **для канонического текста** —
  редактор, открывший и сохранивший golden-файл, не переписывает его целиком.
  Текст, написанный руками, при первом `Write` нормализуется (лишние `:1`,
  порядок токенов, `dr` → `dl`, `LS` → `ls`); смысл при этом не меняется.

## 6. Чего в тексте нет

- `raw_key` и `dik_key` (сырые коды клавиш меню) и `when_enemy` (условие по
  врагу): при попытке записать такой документ в текст конвертер отдаёт ошибку с
  номером команды, а не теряет поле молча. Полный формат — только JSON.
- Битов направлений как отдельных токенов: движение идёт стиком (см. §3.1).
- Прогонных ручек (`POST /rng`, `/dt`, `/fps`, `/render`): это состояние мода для
  конкретного прогона, а не часть скрипта.
- Входов, которых нет в моде: «Aim sub-weapon» (L2/LB) и отдельного `execute` —
  Execute выражается макросом `by` (Y+B на одном кадре).

## 7. Валидация

Тексты проверяются теми же лимитами, что и JSON (`API.md` §4.4): `commands` не
пуст, `duration ≥ 1`, `t + duration ≤ 3600`, `name ≤ 64`, `input` не пуст,
`trigger` с `pos` или `ticks`, `camera`/`left_stick`/`trigger.pos` — нужное число
чисел. Ошибка текста называет строку (`line 3: unknown token 'zz' — a pad button,
a stick token or `by``), лимит — команду (`commands[4]: t+duration exceeds max
3600`).

## 8. Гарантии round trip (и чем они проверены)

| Гарантия | Тест |
|----------|------|
| DSL → документ → DSL — байт-в-байт (для канонического текста) | `ScriptGoldenTests`, `ScriptDslTests` |
| JSON фикстуры → документ → JSON — fixed point | `ScriptJsonTests` |
| JSON, записанный редактором, принимается **модом** и совпадает с фикстурой | Rust-тест `tools/script_gen/tests/expected_json_is_accepted.rs` |
| Текст и JSON — один и тот же скрипт: правила точно, кадры совпадают (кроме битов направлений, которые текст несёт стиком) | `ScriptGoldenTests` |
| Кадры таблицы: `Expand(Collapse(Expand(doc))) == Expand(doc)` | `ScriptFramesTests` |
| Команды с `raw_key`/`dik_key`/`when_enemy` в кадры не попадают (нет колонки) | `ScriptFramesTests` |

## 9. Инструменты

- **Фикстуры.** Rust-тул `tools/script_gen` собирает JSON-фикстуры **из общих DTO**
  (`replay-types/src/script.rs`) — тех же, которыми мод десериализует запрос:

  ```bash
  cargo run -p drmod-script-gen            # в tas-editor-cs/TasEditorCs.Tests/Fixtures
  cargo run -p drmod-script-gen -- --out <каталог>
  ```

- **Golden-файлы редактора.** Рядом с фикстурой `<имя>.json` редактор пишет
  `<имя>.expected.json` (её же JSON) и `<имя>.expected.tas` (её же текст).
  Перегенерация — после осознанного изменения формата:

  ```bash
  set TAS_REGEN_GOLDENS=1 && dotnet test TasEditorCs.slnx
  ```

- **Конвертер.** `TasEditorCs/Script/ScriptDsl.cs` (`Write`/`Parse`),
  `ScriptJson.cs` (`Read`/`Write` + лимиты), `ScriptFrames.cs` (`Expand`/`Collapse`).
